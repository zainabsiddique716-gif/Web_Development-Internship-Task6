# Shipshape Focus Board

A small static focus board shipped as the practical exercise for the combined code-review and deployment track. Click any task to cycle it through `planned`, `in-progress`, and `done`.

## Run locally

```text
npm run verify
npx serve dist
```

The project has no runtime dependencies. `npm run verify` runs the repository lint check, Node's built-in test runner, and the static build.

## Delivery workflow

This repository uses GitHub Flow:

- `main` is always releasable.
- Feature branches use `feature/<short-description>` and merge back through a pull request.
- `.github/workflows/ci.yml` runs on every PR to `main`. Configure the `Quality gate` check as a required status check in branch protection so a failed check blocks merging.
- A merge to `main` runs `.github/workflows/deploy-staging.yml`, which publishes `dist/` to the GitHub Pages `staging` environment.
- `.github/workflows/production.yml` is manual only. Protect the `production` environment with required reviewers in repository settings before using it.

Staging and production intentionally have different triggers: staging is an automatic integration signal after reviewed code lands, while production is a deliberate, auditable release decision. Sharing a trigger would allow every merge to become a customer-facing release and remove the final approval boundary.
